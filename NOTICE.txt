1. Project history

The original public project baseline is:
  aed97db67b7dbd6d4d35678b4c0c609cf2050014
Its Git author is GFDDFDGHJ. That baseline implemented the AML Add/Search
service using FastAPI, SQLite/sqlite-vec and Ark embeddings, with retrieval
and a keyword governance hook. This historical description is not the
current model configuration.

The Textual v3.14.0 algorithm source is:
  db43d67ea1728497ab7b5418a2fd9c62a5c29b71
The final publication revision is recorded separately in the release packet's
release-reference.txt after publication; it must match the submitted service.
Licensing, source disclosures and submission-document corrections do not
represent a new retrieval method or a new evaluation result.

Relative to the original baseline, this Textual implementation changes:
- embeddings to standard text-embedding-v4, 1024 dimensions;
- retrieval to exact user-scoped cosine scoring, lexical/source recall and
  optional bounded qwen3-rerank, with deterministic fallback;
- synchronous, persistent request-id retry/conflict handling and source,
  role, session, sequence and timestamp provenance;
- deterministic extraction of facts, preferences and rules, role-aware state
  history, late-arrival handling and conservative assertion qualification;
- query-scoped rule/procedure context, explicit source-reference links,
  declared table schemas and observations, extractive summaries and bounded
  source continuations that retain original evidence and disclose omissions;
- explicit private-field exclusions, source-scope controls and disabling
  the legacy substring governance feature by default;
- request logging that records operational metadata rather than message or
  query payloads, plus independent synthetic regression checks.

The name MemoryShield+ is this project's name. This submission does not
claim to reproduce a particular MemoryShield/MemoryShield+ paper or to be
affiliated with any paper's authors. The repository's current history and
source notices are the provenance evidence; an author name in Git alone is
not a proof that every line was independently authored.

3. Submission and evaluation boundaries

This notice covers the Textual entry. The separate Coding directory states
its reuse of the Textual bounded reranker client in coding/README.md.
The ingress directory contains the shared transport and its own source
manifest; include that material when describing the deployed public API.

Add and Search make no generative LLM calls and return stored evidence, not
generated final answers. The LLM-free eligibility question remains pending
official clarification; no eligibility approval is claimed here.
Official requirements: https://agentmemories.ai/docs
Model-scope discussion: https://github.com/AML-memory/agent-memory-leaderboard/issues/19

Official evaluation memories, questions, answers, credentials, runtime
databases and derived copies are excluded from this source disclosure.
